Codec browser compatibility

Each cell shows the movie itself, played by this browser, with whether it plays and whether its colors match the source (a few patches of each frame are compared with the source image, two ways: the decoder's own output, read through WebCodecs and converted here with the matrix the browser reports, or, where the browser does not give the decoded samples (hardware-decoded frames, for example), a copy of the frame drawn to a canvas, marked "(canvas copy)". A browser's canvas copy is not always what it shows: Chrome's is off for software-decoded 4:2:2 and 4:4:4, though the screen is right. Firefox's copies have the same error (blue off by up to about 9, from BT.601's Cb coefficient) for every Y'CbCr movie, and it too shows them correctly, so a copy with exactly that error counts as OK. "Reduced chroma" means the colors are right but the browser shows the movie with less chroma resolution than the file has (Firefox shows HEVC 4:4:4 as 4:2:2); compare by eye with the viewer made by tests/codec-color-compare.py. Hover over a result for every number; "Wrong colors" means the browser decoded it but interpreted it wrongly). The gray line under each result is what the browser claims through MediaCapabilities: "hw" when it reports power-efficient (usually hardware) decoding. Y'CbCr files are converted from RGB with zscale (BT.709, limited range); all are tagged BT.709 primaries, sRGB transfer.

Testing…

"Measure the screen" asks to share this tab (choose this tab), then scrolls through the page and records each movie as the browser draws it, compared with the other movies and with the source image in the same capture. The numbers are added to the results (hover over a cell) but do not change them: a tab capture can draw video differently from the screen. Nothing leaves your computer. Best in Chrome or Edge, which can share a single tab.

Submitting sends the results above, your browser's user agent and GPU name, and your note, to a Google Sheet kept by the ORI Encoding Guidelines project.
